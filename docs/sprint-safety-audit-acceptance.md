# Sprint safety and usability audit acceptance

- Preserve the one-lesson, shared student/teacher design and existing storage,
  recording, publication, sync and manual-transfer architecture.
- Check 320px/mobile layouts, named media controls/visuals, readable touch targets,
  keyboard help-dialog focus/return, reduced motion and mandatory typed help.
- Re-run actual captured-audio playback, complete-download/offline reopen,
  independent A/B questions/checks/progress, sync errors and acknowledged returns.
- Verify that edited unsafe/unreviewed instructional content cannot retain a demo
  approval through collection, persistence or publication boundaries.
- Confirm no external AI or remote speech is used on the learner core path, and
  document source-ID validation versus actual teacher factual/safety review.
- Qualify privacy claims by actual device/configured-service data flow; disclose
  public demo PINs, unencrypted teacher audio, unlocked sessions and device limits.
- Fix material demonstrated defects only. Leave production authentication/cloud,
  transcription, hardware deployment and general authoring outside sprint scope.
- Run available contract freshness, types, unit tests, builds, fixture validation
  and browser scenarios; document missing lint and all unverified hardware checks.
- Report residual risks by severity, mitigation and whether they block the local
  simulated hackathon journey versus real-school deployment.
