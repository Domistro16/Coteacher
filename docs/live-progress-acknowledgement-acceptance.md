# Audible source-checking acknowledgement

Operator report: the corrected answer eventually plays, but a long silent gap
precedes it instead of an audible lesson-source checking acknowledgement.
Saved provider transcripts include natural prefacing words before that message.

Acceptance:

- For a pending educational question, send one brief real GPT-Live progress
  commentary without waiting for source retrieval, sync or answer generation.
- Permit bounded non-instructional acknowledgement fragments from their first
  safe words, including partial-word transcript events and common introductions.
  Do not require the word "checking" to arrive before permitting the first words.
- Keep educational speech muted until the checked backend result is returned.
  Any progress text that adds teaching content must be rejected by the gate.
- A fast prepared/procedural result cancels the delayed checking message. New
  learner speech, stopping, returning and switching profile cancel stale progress.
- Preserve the current live session, floating player, sourced explanations,
  generated quiz, teacher recording and all saved histories. No browser TTS or
  prepared clip is substituted for GPT-Live acknowledgement.
- Verify the fragmented-output regression first, then focused live controls,
  builds and real provider acknowledgement timing where available. Decoded media
  or generated transcript evidence is not a human hearing confirmation.
